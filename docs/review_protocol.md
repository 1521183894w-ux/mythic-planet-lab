# 评审流程（Review Protocol）

> 每个检查点都要走这套流程。目的：让"像不像真世界、够不够险奇"这种判断有固定的材料和固定的步骤，而不是由开发者自评。

---

## 1. 流程

```
开发完成一个单元
  → 运行 scripts/make_figures 生成标准图组
  → 运行 scripts/compute_metrics 生成指标报表
  → 调用 world-reviewer 子 agent 评审（它只看图、指标和创作简报，不看代码）
  → 开发者处理"严重"问题，或在报告中说明为何暂不处理
  → 更新 PROGRESS.md，提交 Git，向用户汇报
  → 用户看图，在 PROGRESS.md 写下"通过"或修改意见
```

- 开发者**不得**修改评审报告的内容，只能在报告后追加"开发者回应"。
- 评审报告存放在 `reviews/stageN_<日期>_<序号>.md`。
- 评审中如果 `world-reviewer` 指出问题而开发者不同意，把分歧原样写进汇报，交给用户裁决。

## 2. 标准图组

### 2.1 通用规则

- 所有图存放在 `figures/stageN/<世界ID或种子>/`，文件名固定，便于跨版本对比。
- **固定色带与图例**：
  - 高程：分层设色 + 山体阴影（hillshade），海平面处颜色明确断开；陆地与海洋色带在所有图中一致。
  - 连续变量使用感知均匀色带（如 viridis、cividis）；正负变量用发散色带。
  - 每张图带比例尺、经纬网、图例、单位、`method_class` 标签、种子和代码版本号。
- 全球图使用**等距圆柱投影**（2:1）。极区另出**两张极地投影图**（例如正射或兰勃特等积方位投影），避免极地变形掩盖问题。
- 每次输出一个 `index.html` 静态画廊页，方便用户在浏览器中翻看和对比。

### 2.2 区域放大图（必需）

低分辨率全球图会抹掉半岛和群岛，**这可能是上一轮自评"通过"的原因之一**。所以每个图组必须包含区域放大图：

- 每个世界至少 **8 张**约 2000 km × 2000 km 的区域裁剪图，按以下规则自动选取：
  1. 主内海全貌；
  2. 主内海中海岸最复杂的一段；
  3. 主大陆北端高纬海岸；
  4. 极地大陆的一段海岸；
  5. 一处亚大陆之间的陆桥或地峡；
  6. 海岸复杂度**最低**的一段（专门暴露问题）；
  7. 最大的群岛区；
  8. 随机抽取的一段海岸（防止只挑好看的）。
- **每张区域图旁边并排放一张同比例尺、同分辨率的地球区域图**作为对照（从 `data/earth_reference/regions/` 中选择性质相近的区域，例如内海对照地中海、北端海岸对照挪威、群岛对照东南亚）。
- 区域细化阶段之后，区域图使用区域高分辨率结果，并注明分辨率。

### 2.3 各阶段图组

| 阶段 | 必需图 |
|---|---|
| 0 | 地球基准图：同分辨率的高程、海岸、各指标分布图；地球区域参照图集 |
| 1 | 海陆与高程；板块与边界类型；地壳类型与洋壳年龄；岩性；主要构造事件时间线；若干关键年代（例如 300、200、100、50、0 Ma）的古地理图；高程曲线与地球对比；**多种子联系表** |
| 2 | 高程 + 阴影（细化后）；坡度；河网与流域；内流区；湖泊；海岸复杂度指标图；奇景原型的潜在地点标注；与地球的坡度、Hack 定律对比图 |
| 3 | 年平均与季节温度；年降水与季节性；风场（标注来源等级）；Köppen 分类；冰盖与冰期最大范围；生物群系；主内海潮差图与"神怒"海湾标注；与地球的纬向剖面对比 |
| 4 | 编辑前后对比图；受影响图层清单；锚点位置与成因说明 |
| 5–6 | 三维界面截图与操作录屏（以实际运行为准） |

## 3. 评审报告模板

```markdown
# 评审报告 · 阶段 N · <世界ID或种子> · <日期>

## 总体印象（3–5 句）
如果把这张图混进地球古地理图集，能否一眼认出是假的？为什么？

## 问题清单
| # | 严重程度 | 对应简报条目 | 现象（指出具体图和位置） | 可能原因 | 建议 |
|---|---|---|---|---|---|
| 1 | 严重/一般/轻微 | vision §3 | ... | ... | ... |

## 亮点
值得保留的地方。

## 指标与观感是否一致
指标达标但观感不佳之处；或观感好但指标不达标之处。

## 奇景原型
已出现 / 潜在 / 缺失的原型。

## 结论
- 是否建议提交给用户：是 / 否（附理由）
```

严重程度定义：
- **严重**：违背创作简报的核心要求，或触犯 CLAUDE.md 禁区清单。例如海岸圆润、主大陆被切断、荒漠主导、地形由噪声主导。
- **一般**：明显不像地球，但不影响整体方向。
- **轻微**：细节或美观问题。

---

## 4. 用户确认格式

在 `PROGRESS.md` 的"用户评审"部分写：

```
### <日期> 阶段 N
结论：通过 / 不通过 / 有条件通过
意见：
- ...
```

只有用户写下"通过"或"有条件通过"，阶段才算完成。
